01The problem

Conventional street lights burn at full power from dusk to dawn, even on an empty road at 3 a.m.

Faults are usually found when a resident complains. LumenCity treats every light as an intelligent agent that senses its surroundings and picks its own brightness. A control centre watches the whole network, measures the energy saved and sends repair crews along the shortest road path when a lamp fails.

02How each light decides

Every light runs the same rules on every tick, in priority order, and then fades smoothly toward its target level:

if light is faulty             → OFF
if emergency                   → 100%
if manual override             → override level
if zone mode = Manual / Off    → manual level / 0
if ambient light is bright     → OFF            # LDR
base = zone base level (or active schedule)
if Eco mode                    → base reduced, max 80%
if rain or fog                 → base + 20%
if motion detected             → 100% (80% in Eco)  # PIR

Energy model. A smart LED draws 90 W at full brightness plus 1.5 W for its controller. A conventional sodium lamp draws 150 W from 18:00 to 06:00. CO₂ is calculated at 0.82 kg/kWh (Indian grid average) and cost at ₹8/kWh.

03Architecture

  1. NodeSmart lightLED + LDR + PIR on an ESP32
  2. NetworkZone gatewayLoRa / Wi-Fi mesh
  3. BrainControl centrePolicies, schedules, analytics
  4. ActionMaintenanceAlerts and crew dispatch

In the dashboard, data packets travel along the roads from the control centre to each light, and a fault sends a red alert packet back. The code is split into a simulation engine (sim.js), a canvas map renderer (map.js), animated scenes, hand-written SVG charts and the UI layer.

05What's inside

  • Live city map. Day/night cycle, traffic signals with queueing cars, headlight beams, pedestrians, rain and fog. Zoom, pan, and click to inspect.
  • Zone control. Downtown, Residential, Central Park, Industrial and Market, each with Auto / Eco / Manual / Off modes.
  • Energy analytics. Hourly smart vs. conventional energy, a savings ring, weekly savings and live load by zone.
  • Fault detection. Lamp failure, driver overheating, communication loss and voltage faults. Repair vans drive from the depot, fix the light and return.
  • Schedules. Time-based rules on a 24-hour timeline, for example the park switches off from 01:00 to 05:00.
  • Hardware sketch. An ESP32 program runs the same logic with an LDR, a PIR sensor and a PWM-dimmed LED. It hasn't been tested on physical hardware yet.
